# GPS 현재 위치 마커 — 모바일 롱프레스 정밀도 수정

생성: 2026-08-25 12:37

## 배경

이번 세션에서 GPS 흐름을 재설계했다: `app.py`가 아니라 프론트(`route-optimizer/static/js/`)
쪽 변경이다. 이제 GPS(새로고침 자동요청 + 📍 버튼)는 출발/도착지를 자동 지정하지 않고
지도에 "현재 위치" 마커(파란 핀, 📍)만 찍는다(`map.js`의 `setGpsMarker(latlng, onContextMenu)`,
`app.js`의 `_applyCurrentLocation`/`setupGpsButton`). 사용자가 그 마커를 **우클릭**해야
"여기서 출발"/"여기서 종료" 메뉴가 뜨고, 선택하면 좌패널에 반영된다.

이 흐름을 만들면서 원래 있던 버그도 같이 고쳤다: 마커를 우클릭하면 지도 자체의
빈 공간 우클릭 핸들러(`map.js`의 `map.on("contextmenu", ...)`, `initMap` 안)로 이벤트가
새어나가, 마커의 정확한 좌표가 아니라 "마우스 커서가 찍힌 화면 픽셀을 위경도로
역산한 값"을 쓰고 있었다 — 그래서 지도를 확대해보면 마커 바로 옆에 살짝 어긋난
지점이 잡히는 문제가 있었다(사용자가 직접 재현해서 보고함). 고친 방법:
`setGpsMarker` 안에서 마커 자신에게 `contextmenu` 리스너를 달고
`e.originalEvent.stopPropagation()` + `e.originalEvent.preventDefault()`로 지도 레벨
핸들러로 새지 않게 막은 뒤, 클로저로 캡처해둔 정확한 `latlng`을 그대로 콜백에 넘긴다.

**이 수정은 데스크톱 우클릭(`contextmenu` 이벤트)만 다룬다.** 모바일 롱프레스는
아직 손대지 않았다 — 사용자가 "필요하면 다음에 처리"라고 명시적으로 미룬 부분이다.

## 왜 롱프레스도 같은 문제일 가능성이 높은가

`map.js`의 `_attachLongPress(map)`(약 318~341번째 줄)는 `map.on("touchstart", ...)`로
**지도 전체**에 걸어두고, 500ms 타이머 뒤 항상 아래처럼 좌표를 계산한다:

```js
const latlng = map.containerPointToLatLng(
  map.mouseEventToContainerPoint({ clientX: touch.clientX, clientY: touch.clientY })
);
if (_onContextMenu) _onContextMenu(latlng, touch.pageX, touch.pageY);
```

터치가 마커 아이콘 위에서 시작했는지 여부와 무관하게 항상 이 픽셀 역산 좌표를 쓴다.
마커 자체엔 touchstart 리스너가 없어서 네이티브 이벤트가 그대로 지도 컨테이너까지
버블링돼 이 핸들러가 걸린다 — 데스크톱 우클릭 버그와 근본 원인이 완전히 같다.

## 해야 할 일

1. `setGpsMarker`가 만드는 마커(`_gpsMarker`/`_gpsMarkerM`)의 아이콘 DOM 요소에
   전용 `touchstart`/`touchend`/`touchmove` 리스너를 달아, `_attachLongPress`와 같은
   500ms 타이머 롱프레스를 마커 레벨에서 별도로 구현한다.
2. 타이머 만료 시 `e.stopPropagation()`(또는 touchstart 단계에서 미리)으로 지도 레벨
   `_attachLongPress`의 타이머가 같이 돌지 않게 막는다 — 안 그러면 두 메뉴가 동시에
   뜨거나 경합이 생길 수 있다.
3. 콜백은 기존과 동일하게 마커의 정확한 `latlng`을 써서 `onContextMenu(latlng, pageX, pageY)`
   호출 — `app.js`의 `_onGpsPinContextMenu`를 그대로 재사용하면 됨(수정 불필요, 이미
   출처 무관하게 latlng을 그대로 받아 `showContextMenu`를 연다).
4. `L.Marker`가 Leaflet 내부적으로 이미 자체 DOM에 리스너를 붙이는 구조라(`_initInteraction`),
   원시 DOM `addEventListener`보다는 `marker.on('touchstart', ...)` 같은 Leaflet API가
   있는지 먼저 확인 — 없으면 `marker.getElement()`로 아이콘 DOM을 얻어 직접 붙인다.

## 판단 기준 / 스코프

- **범위는 GPS 마커 하나로 한정한다.** 저장된 지점 마커나 출발/도착지 앵커 핀(`1`/`🏁`)의
  롱프레스는 이번 요청과 무관 — 사용자가 이번 세션에서 명시적으로 "좌패널 목록에 있는
  저장된 지점을 지도에서 우클릭하는 동작은 손대지 말라"고 확인했다(데스크톱 우클릭 범위
  결정이지만 롱프레스도 같은 스코프 결정을 따르는 게 자연스럽다 — 다만 이 부분은 다음
  세션에서 사용자에게 다시 한번 확인해도 됨, 명시적으로 롱프레스 스코프까지 확답받진 않았음).
- 완료 판정은 "실제 모바일 기기(또는 최소한 브라우저 개발자도구 터치 에뮬레이션)에서
  롱프레스 → 정확한 좌표로 메뉴가 뜨는지"까지 확인해야 한다 — 데스크톱에서 마우스로
  touch 이벤트를 synthetic dispatch하는 것만으로는 실제 터치 좌표 계산 차이(예:
  `touches[0]` vs `changedTouches[0]`)를 완전히 재현하지 못할 수 있으니 주의.

## 검증에 쓴 방법 (참고용 — 이번 세션 데스크톱 수정 검증)

Playwright로 `navigator.geolocation.getCurrentPosition`을 monkeypatch해 고정 좌표를
반환하게 한 뒤, 📍 버튼 클릭 → 마커의 `.anchor-pin-label` 요소 `getBoundingClientRect()`
중심에 synthetic `mousedown`/`mouseup`/`contextmenu`(`button:2`)를 dispatch해서
"여기서 출발" 클릭 후 좌패널 라벨이 마커의 정확한 좌표와 일치하는지 확인했다. 롱프레스도
같은 패턴으로(touchstart→500ms 대기→touchend 또는 직접 라이브러리가 만드는 이벤트 발화)
재현하면 될 것으로 보인다.
