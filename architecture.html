01 — 전체 구조

앱은 3개 층으로 이루어져 있습니다

사용자 PC에서 Flask를 실행하고, 같은 와이파이의 스마트폰에서 브라우저로 접속합니다. 서버는 최적화 계산만 하고, 지도는 브라우저가 그립니다.

🌐 프론트엔드 레이어 — 브라우저 (스마트폰 / PC)
Leaflet 지도 위에 지점 마커를 표시하고, 사용자 조작을 받아 서버에 요청을 보냅니다. 결과(최적 순서·타임라인·경로선)도 여기서 화면에 그립니다.
app.js map.js selection.js optimize.js timeline.js multiday.js Leaflet.js Bootstrap 5
⇄   HTTPS 요청/응답  — 같은 와이파이 LAN

HTTP 요청을 받아 최적화를 실행하고 JSON으로 응답합니다. 서버가 켜질 때 자동으로 SSL 인증서를 만들고, 백그라운드에서 거리 행렬을 미리 계산해 둡니다.

03 — 요청 흐름

최적화 버튼을 누르면 무슨 일이 일어날까?

1
브라우저 — selection.js / app.js
지점 선택 + 출발지 설정
마커 클릭 또는 사이드바 체크박스로 지점 선택 → state.selected(Set)에 id 저장. GPS 버튼 또는 지도 롱프레스로 출발지 좌표 설정 → state.origin에 저장. 선택 2개 이상 + 출발지 있을 때 [최적화] 버튼 활성화.
2
브라우저 → 서버 — optimize.js
POST /api/optimize 전송
fetch('/api/optimize', {method:'POST', body: JSON.stringify({...})}) 로딩 스피너를 띄우고 서버에 JSON 전송: 선택된 지점 id 배열 · 출발지 좌표 · 시작시각("09:00") · 체류시간(분)
3
서버 — distance_matrix.py
거리 행렬 조회 or 계산
get_matrix(coords, keys)가 필요한 좌표 쌍을 먼저 캐시에서 확인. 캐시 미스 시 OSRM Table API를 한 번에 호출해 N×N 전체 행렬 획득. OSRM 10초 초과 or 실패 → Haversine × 1.4, 60km/h로 즉시 대체. 응답에 source: "osrm" | "haversine" 포함.
4
알고리즘 — optimizer.py
OR-Tools TSP 풀기
solve(matrix, start_idx, end_idx) — 이동시간 행렬을 입력해 최단 방문 순서(인덱스 배열) 반환. 탐색 전략: PATH_CHEAPEST_ARC 초기해 + 시간 제한 1초. 20개 이하에서는 최적해 or 그에 가까운 해를 1초 내 반환.
5
서버 — app.py
타임라인 + 경로선 조립
최적 순서대로 각 구간 drive_min, arrive, depart 계산 (_build_legs). OSRM Route API로 실제 도로 경로 좌표(polyline) 가져오기 (_build_polyline). Route API 실패 시 직선 좌표 배열로 폴백 — 어떤 경우에도 빈 값은 반환하지 않음.
6
브라우저 — map.js / timeline.js
결과 렌더링
지도에 ①②③… 번호 DivIcon 마커 표시. 도로를 따라 파란 경로선 그리기. 타임라인 패널에 구간별 도착·출발 시각, 합계(총 km·종료시각) 표시. source === "haversine"이면 "거리 근사치" 경고 배너 노출.
04 — 핵심 기술

알아두면 좋은 개념 3가지

🔢
TSP (외판원 문제)
OR-Tools · Google
N개 지점을 가장 짧은 경로로 한 번씩 모두 방문하는 순서를 찾는 문제. 지점이 10개만 돼도 가능한 순서가 수백만 가지인데, OR-Tools가 수학적 탐색으로 1초 내에 최선에 가까운 답을 계산합니다.
도착지 없음 → 마지막 지점에서 끝 (Open TSP)
도착지 있음 → 반드시 그 지점에서 끝 (종단 고정)
이 분기 처리를 위해 가상 depot 노드 트릭 사용
🛣️
거리 행렬 & 캐시
OSRM · Haversine 폴백
"직선 거리"가 아닌 실제 도로를 따른 이동 시간이 필요합니다. OSRM에 N개 좌표를 보내면 N×N 행렬을 한 번에 돌려줍니다. 이 결과를 메모리에 캐시해두어, 이후 요청은 API 없이 즉시 응답합니다.
서버 시작 시 prefetch.py가 미리 75×75 = 5,625쌍을 계산
OSRM 실패 → Haversine × 1.4 (직선거리 × 도로 우회율)
실패 여부는 배너로 사용자에게 표시
🔐
자동 HTTPS & GPS
cryptography 라이브러리
스마트폰 GPS(navigator.geolocation)는 HTTPS에서만 동작합니다. 앱이 시작될 때 현재 PC의 LAN IP를 확인하고, 그 IP를 SAN에 포함한 자체 서명 인증서를 자동으로 생성합니다.
cert.pem + key.pem 없으면 자동 생성
IP가 바뀌면 인증서도 자동 재생성
아이폰은 /cert 에서 인증서 설치 후 신뢰 설정 필요 (최초 1회)

06 — 확장 기능

N일 계획은 어떻게 다를까?

75개 지점 전체를 며칠에 걸쳐 나눠 방문할 때 사용합니다. 단순히 최적화를 N번 하는 게 아니라, 먼저 날별로 지점을 배분한 뒤 각 날을 최적화합니다.

1
그룹 표시 — 미방문 지점 전체를 지도에 표시, 배분할 지점 선택
2
일수 추정 — /api/estimate-days 호출로 몇 일 필요한지 빠르게 계산
3
날짜별 패널 설정 — 각 날의 출발지·도착지 설정
4
greedy 배분 — assign_days()가 하루 업무 시간 내에 들어오도록 지점을 날별로 배정
5
날별 TSP — 각 날 배정된 지점에 대해 개별 최적화 실행
6
결과 표시 — 날별 탭으로 타임라인·경로선·요약 표시. 마지막 날 초과 시 경고
